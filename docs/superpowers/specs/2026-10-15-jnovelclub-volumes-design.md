# J-Novel Club owned volumes

Date: 2026-10-15
Status: approved design, awaiting implementation plan
Branch: `feat/jnovelclub-volumes`, based on `feat/jnovelclub-parts` (PR #254), which is based on
`feat/light-novels` (PR #251).

## Goal

Every volume the user owns on J-Novel Club, for a series mapped to J-Novel Club, is downloaded as
J-Novel Club's own official EPUB. It sits in the same Komga series as that series' parts, right
after the parts it collects, and is downloaded again when J-Novel Club revises it.

This is piece 2 of 3:
- **Piece 1, parts** (`2026-10-14-jnovelclub-parts-design.md`): done, PR #254.
- **Piece 3, volume progress:** writing volumes read to MAL and AniList. Out of scope here; it will
  read finished volumes from the table this piece adds.

## Decisions taken with the user

| Question | Decision |
|---|---|
| Where volumes sit in Komga | **The same series folder as the parts.** Soshuhen sets and locks each volume book's number and sort position through Komga's API. |
| Order inside the series | **Right after the volume's own parts.** `numberSort` is the volume's last part number + 0.5, so volume 16 (parts 204–216) sorts at 216.5. |
| When to download | **Automatically, for series mapped to J-Novel Club.** Buying the volume is the decision. Pre-orders wait. Owned volumes of unmapped series are only reported. |
| A revised volume (`lastUpdated` newer) | **Replace the file in place**, atomically. The old edition is not kept. |
| Volumes and parts together | Unchanged from piece 1: **keep both**. Part files are never removed because a volume is owned. |
| Approach | **A `volume` table plus a library-sync job.** Chapters are untouched. |
| Account | The account currently signed in has an empty library and no Premium (created 2026-10-14). The user chose to design from first-party evidence now; a real download stays unverified until the account owns a volume. |

## Evidence

J-Novel Club publishes no API documentation. The sources:
- its web app's protobuf message definitions (from the research for piece 1);
- three open-source clients that download owned books: `jnoveldl`, a C# downloader, and
  `jnc_api_tools`;
- J-Novel Club's 2021 developer post (forum topic 4370);
- one live, read-only call made with the user's permission: `GET /app/v2/me/library` answered 200
  `{"books": [], "pagination": {"limit": 100, "skip": 0, "lastPage": true}}`.

| Fact | Source |
|---|---|
| `GET /app/v2/me/library?format=json&include=serie&limit=&skip=` with Bearer → `{books[], pagination{limit, skip, lastPage}}` | live (empty library) and the web app |
| `LibraryBook`: `id`, `legacyId`, `volume`, `serie`, `purchased`, `lastDownload`, `lastUpdated`, `downloads[]`, `status` | web app message definition |
| In JSON, `lastUpdated` and `lastDownload` are ISO date strings, and `status` is a string such as `"PREORDER"` | C# client (`DateTime.Parse`), `jnc_api_tools` (`item['status'] == 'PREORDER'`) |
| `Download {link, type, label}`; in JSON `type` is a name such as `"EPUB"` | web app, `jnoveldl` (`d.get("type") == "EPUB"`) |
| The EPUB `link` is fetched with a plain GET and no Authorization header. The links carry their own authorisation, should not be stored, and should be read fresh from the library. | `jnoveldl`, the C# client, J-Novel Club forum topic 4370 |
| A newer `lastUpdated` means J-Novel Club revised the file | forum topic 4370, C# client |
| Each volume's parts, for the sort position, come from `/aggregate` (already used by piece 1) | live |
| `PATCH /api/v1/books/{bookId}/metadata` accepts `number` (string), `numberLock`, `numberSort` (float) and `numberSortLock`; omitted fields are unchanged | Komga `BookController.kt` and `BookMetadataUpdateDto.kt` (master, 2026-10-15) |

**Unverified until the account owns a volume:**
- whether `link` redirects, to which host, and how long it stays valid;
- the download's content type;
- the full set of `status` values;
- whether J-Novel Club's own EPUB carries series metadata Komga would otherwise use.

The design does not depend on any of these. It follows redirects, checks the bytes rather than the
content type, treats every status but `PREORDER` as owned, and locks the number and sort position.

## 1. Data model

Migration `0023_volume` creates:

```sql
create table volume (
    id bigint generated by default as identity primary key,
    series_id bigint not null references series(id) on delete cascade,
    number numeric(8, 2) not null,
    source_volume_id text not null,
    title text,
    status text not null check (status in ('owned', 'preorder')),
    last_updated timestamptz,
    downloaded_updated timestamptz,
    first_part numeric(8, 2),
    last_part numeric(8, 2),
    state text not null default 'known'
        check (state in ('known', 'queued', 'downloading', 'downloaded', 'failed')),
    file_path text,
    komga_book_id text,
    discovered_at timestamptz not null default now(),
    unique (series_id, number),
    unique (series_id, source_volume_id)
);
```

- `downloaded_updated` is the `last_updated` of the file on disk. A volume needs downloading again
  when `downloaded_updated` is null or older than `last_updated`.
- An ORM model `Volume` sits in `models.py`.
- `chapter` is unchanged, so nothing that counts or numbers chapters sees volumes.
- Download links are never stored.
- Owned volumes of series that are not mapped get no row.
- A volume that leaves the library keeps its row and file. Its row just stops updating.

## 2. Reading the library

### Source methods (`sources/jnovelclub.py`)

Pure: they take arguments and return values.

```python
@dataclass(frozen=True)
class OwnedVolume:
    series_slug: str
    volume_id: str
    number: Decimal
    title: str | None
    status: str            # "owned" or "preorder"
    last_updated: datetime | None
    epub_link: str | None
```

- `async library() -> list[OwnedVolume]` pages `GET /app/v2/me/library?format=json&include=serie&limit=100&skip=N` until `pagination.lastPage`. It needs a sign-in (`SignInRequired`), and a 401 follows piece 1's rule: invalidate, then `SignInRequired`.
  - `status` is `"preorder"` when the entry's status is `PREORDER`, otherwise `"owned"`.
  - `epub_link` is the `downloads` entry whose `type == "EPUB"`, otherwise `None`.
  - `parse_library(payload) -> list[OwnedVolume]` is the pure parser.
- `async part_ranges(series_slug) -> dict[Decimal, tuple[Decimal, Decimal]]` maps each volume number to its first and last part number, from `/aggregate`. `parse_part_ranges(payload)` is the pure part.

### Job `jnc_library_sync` (fetch lane)

It is a new `JobType`, with a cron setting `cron_jnc_library_sync` (default `0 */6 * * *`) in the
existing cron registry (`app.cron.CRON_JOBS`), shown in Settings with the other crons.
`POST /api/sources/jnovelclub/sign-in` and a new `POST /api/sources/jnovelclub/library-sync` also
queue it (dedupe key `jnc_library_sync`).

1. If the J-Novel Club source raises `SignInRequired`, log "J-Novel Club is not signed in; skipping the library" and finish as **done**. A free or signed-out install must not produce a failed job every 6 hours.
2. Call `library()` and group the volumes by `series_slug`.
3. Map each slug to a series: `source_mapping.active` with `source_site = 'jnovelclub'` and `source_url` ending in `/series/{slug}`. Slugs that match nothing are collected for the log.
4. For each matched series, call `part_ranges(slug)` once, then upsert every volume on `(series_id, source_volume_id)`. The upsert writes `number`, `title`, `status`, `last_updated`, `first_part` and `last_part`, and never `state`, `file_path`, `komga_book_id` or `downloaded_updated`.
5. Queue a volume (set `state = 'queued'`, enqueue `volume_download {volume_id}` with dedupe key `volume_download:{id}`) when all of these hold:
   - `status = 'owned'`;
   - the library entry has an EPUB link;
   - `state` is not `queued` or `downloading`;
   - `downloaded_updated` is null or older than `last_updated`.
6. Log: owned, newly queued, revised, pre-orders waiting, and "owned on J-Novel Club but not mapped: `<titles>`".

## 3. Downloading a volume

### Job `volume_download` (download lane)

It is added to `_DOWNLOAD_LANE` in `enums.py`, so only `worker-download` runs it and writes files.

1. Load the volume, its series slug and `last_updated`; set `state = 'downloading'`.
2. Read `library()` again and find the entry by `volume_id`. If it is gone: `state = 'known'`, `PermanentError("volume <n> is no longer in your J-Novel Club library")`. If it has no EPUB link: the same, with "has no EPUB download".
3. `GET` the link with no Authorization header, through the J-Novel Club `SiteClient` (rate limit 1 request per second, following redirects).
4. Check the bytes with `is_epub(data)`: a zip whose first entry is named `mimetype` and reads exactly `application/epub+zip`. If the check fails, raise an ordinary error, so the retry ladder applies and nothing is placed.
5. Place the file atomically at `volume_path(library_root, slug, number, title)`, with a temp file and `place_file`. If the row's previous `file_path` differs from the new path (the title changed), remove the previous file only after the new one is in place.
6. Update the row: `state = 'downloaded'`, `file_path`, `downloaded_updated = last_updated`. Enqueue `komga_scan` for the series (dedupe `komga_scan:{series_id}`).

**Errors:**

| Case | Result |
|---|---|
| `SignInRequired` | `state = 'known'`; `PermanentError` with the message |
| 403 or 410 on the link | the retry ladder; the next attempt reads a fresh link |
| anything else | the retry ladder, then `failed` |

The downloaded file is never modified.

### Paths (`downloader/paths.py`)

- `volume_filename(series_slug, number, title=None) -> str` returns `"{slug} - Vol.{format_number(number)}[ - {safe title}].epub"`.
- `volume_path(library_root, series_slug, number, title=None) -> Path` is the same, inside `series_dir`.
- `volume_number_from_filename(filename) -> Decimal | None` matches `\bVol\.(\d+(?:\.\d+)?)`.
- `number_from_filename` still matches only `Ch.`, so a volume file is never read as a chapter.

`is_epub` lives in `downloader/epub.py`, next to the writer.

## 4. Komga, API and screens

### `komga_scan`

After chapter reconciliation, a new step `reconcile_volumes(ctx, client, series_id, books)` runs:

1. For each Komga book whose filename gives a `volume_number_from_filename`, find the series' `volume` row with that number. Set `komga_book_id`, and set `state = 'downloaded'` and `file_path` if they are not already set.
2. Wanted values: `number = f"Vol. {format(number)}"`, `numberSort = last_part + 0.5`, or `100000 + number` when `last_part` is null. If the book's current `number`, `numberSort`, `numberLock` and `numberSortLock` already match, do nothing. Otherwise send `PATCH /api/v1/books/{id}/metadata` with `{"number", "numberLock": true, "numberSort", "numberSortLock": true}`.
3. Failures in this step are logged and do not fail the scan, the same as cover handling.

Supporting changes:
- `KomgaClient.update_book_metadata(book_id, body: dict)`.
- `KomgaBook` gains `number: str | None`, `number_sort: float | None`, `number_lock: bool` and `number_sort_lock: bool`, read in `parse_books` from `metadata.number`, `metadata.numberSort`, `metadata.numberLock` and `metadata.numberSortLock`.
- Book-cover backfilling and the mark-read paths already act only on books mapped to chapter rows. The plan confirms this, and skips volume books explicitly if it does not hold.

`progress_push` is unchanged. It ignores Komga books that are not chapter rows, so a finished
volume moves nothing until piece 3.

### API

- `GET /api/series/{id}` gains `"volumes": [{"number", "title", "status", "state", "last_updated", "revised", "komga_book_id"}]`, ordered by number. It is empty for every series with no volumes.
- `POST /api/sources/jnovelclub/library-sync` queues the job and returns `{"ok": true, "job_id": ...}`.

### Screens

- **Series page:** a **Volumes** panel when `volumes` is non-empty. Each row shows "Vol. N", the title and a state badge:

  | State | Badge |
  |---|---|
  | downloaded | Downloaded |
  | queued or downloading | Queued |
  | pre-order | Pre-order |
  | known and revised (`downloaded_updated` older than `last_updated`) | Updated, downloading again |
  | failed | Failed |

  A downloaded volume with a `komga_book_id` has a "Read in Komga" link to `/book/{id}/read-epub`. `revised` is true when `downloaded_updated` is not null and older than `last_updated`.
- **Settings:** a **Sync library now** button on the J-Novel Club card, shown when signed in. The new cron appears in the pipeline settings.

## 5. Testing

**Pure:**

| Subject | Cases |
|---|---|
| `parse_library`, against a payload built from the message definitions and the clients' field names | paging until `lastPage`; EPUB link chosen among several types; `PREORDER` → `preorder`; an entry without an EPUB link; ISO dates parsed |
| `library()` | no sign-in → `SignInRequired`; 401 → invalidate → `SignInRequired` |
| `parse_part_ranges`, against the recorded Apothecary aggregate | volume 16 → (204, 216) |
| `is_epub` | a valid EPUB; HTML; a zip without `mimetype`; a zip with the wrong `mimetype` |
| `volume_filename` / `volume_number_from_filename` | round-trip; `number_from_filename` returns `None` for a `Vol.` name |
| `parse_books` | reads number, sort and locks |

**Against Postgres:**

| Subject | Cases |
|---|---|
| Migration 0023 | table and unique keys |
| `jnc_library_sync`, with a fake source | owned + mapped → row + queued job; pre-order → row, no job; newer `last_updated` → queued again; unmapped series → reported, no row; not signed in → done with a log line, no failure; a repeat run with no changes queues nothing; the upsert never resets `state` or `file_path` |
| `volume_download`, against a stub HTTP server | placed at `volume_path`, row downloaded with `downloaded_updated`, scan queued; a revision replaces in place; a changed title places the new file then removes the old; gone from the library → `PermanentError`, row `known`; HTML body → error, nothing placed; `SignInRequired` → row `known` |
| `komga_scan` volume step, with a fake client | matched by filename; patched with the exact body when the values differ; not patched when they already match |
| API | `volumes` on series detail with the `revised` flag; empty list elsewhere; `POST /library-sync` queues one deduped job |

**Frontend:** `npm run build`, and every new class grepped in `frontend/dist/`.

**Live** (with the user's go-ahead):
- Run the library sync with the signed-in account.
- Expect: done, 0 owned, no rows, no failed job.
- A real volume download stays unverified until the account owns a volume. This spec records that.

## Out of scope

- Volume progress to MAL and AniList (piece 3).
- Volumes of series that are not mapped.
- Buying or pre-ordering through the API.
- Formats other than EPUB.
- Removing part files when a volume is owned.
